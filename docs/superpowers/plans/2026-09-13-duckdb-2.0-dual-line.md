# DuckDB 2.0 Dual-Line Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and test duck_block_utils on both DuckDB lines the community registry builds (v1.5.5 and v2.0-cyanoptera) on every PR, with a CI assertion that our lines are the registry's lines, and carry the same change to the fleet.

**Architecture:** Three build jobs in one workflow (stable, next, advisory canary); a `duckdb-pin` job that reads the registry's `build.yml` and `build_next.yml` at a resolved sha and asserts pin, constant and shipped lines against them; a compat shim that probes the members that changed rather than header presence; error tests that carry the exception's type prefix so class-13 mis-declaration is visible on the 2.0 leg.

**Tech Stack:** GitHub Actions reusable workflows from duckdb/extension-ci-tools; bash for the pin job; C++11-compatible tag-dispatch templates in `src/include/duckdb_compat.hpp`; DuckDB sqllogictest (`build/release/test/unittest --test-dir . "test/sql/<file>"`); `gh` for PRs and dispatches.

**Spec:** `docs/superpowers/specs/2026-09-13-duckdb-2.0-dual-line-design.md`

## Global Constraints

- Stable line: `duckdb_version: v1.5.5`, `ci_tools_version: v1.5-variegata`; the `duckdb` submodule pin stays `d8cdaa33fda8df955cc76ef58a280f68f4cd43fa`.
- Next line: `duckdb_version: v2.0-cyanoptera`, `ci_tools_version: main`. Canary: `duckdb_version: main`, `ci_tools_version: main`.
- Registry authority: `https://raw.githubusercontent.com/duckdb/community-extensions/<sha>/.github/workflows/build.yml` default `inputs.duckdb_version || 'vX.Y.Z'`; `.../build_next.yml` literal `duckdb_version: 'vX.Y-name'`.
- Degraded paths: registry unreachable is a `::notice` plus a summary line; fetched-but-unparseable is a failure; tag resolution failure is a failure.
- Compat shim compiles at C++11: tag dispatch, no `if constexpr` in new code. The 2.0 half cannot be compiled locally; the `duckdb-next-build` job is the only proof of that half.
- Commit messages end with the attribution lines in effect for this session.
- All work lands on branch `ci/pin-equals-shipped-tag` (PR #33), which becomes the dual-line PR.

- [ ] **Step 2: Widen the pin job to two registry lines**

In the `duckdb-pin` job, add `DUCKDB_NEXT: v2.0-cyanoptera` under `env:` beside `DUCKDB_VERSION`, and replace the step's `run:` from the line `n=$(grep -c ...` to the end with:

```bash
          n=$(grep -c "duckdb_version: ${DUCKDB_VERSION}$" .github/workflows/MainDistributionPipeline.yml)
          [ "$n" -ge 1 ] || { echo "::error::no build job in this workflow ships duckdb_version: ${DUCKDB_VERSION}; this job's constant has drifted"; exit 1; }
          m=$(grep -c "duckdb_version: ${DUCKDB_NEXT}$" .github/workflows/MainDistributionPipeline.yml)
          [ "$m" -ge 1 ] || { echo "::error::no build job in this workflow builds the next line duckdb_version: ${DUCKDB_NEXT}"; exit 1; }
          # THE AUTHORITY is the registry's own files, not this job's constants: a
          # constant checked only against itself passes for a year after the registry
          # moves (panduck, 2026-09-13). Resolve main to a sha first so the raw fetches
          # are not served from the branch cache. TWO degraded paths, deliberately
          # different: UNREACHABLE is the world being unavailable -> a NOTE, and the
          # summary says the registry assertions were not made; REACHABLE BUT
          # UNPARSEABLE is this check being wrong about the file -> a FAILURE.
          summary="${GITHUB_STEP_SUMMARY:-/dev/null}"
          base="https://raw.githubusercontent.com/duckdb/community-extensions"
          sha=$(curl -sf https://api.github.com/repos/duckdb/community-extensions/commits/main | grep -m1 -o '"sha": *"[0-9a-f]*"' | grep -o '[0-9a-f]\{40\}' || true)
          if body=$(curl -sf "${base}/${sha:-main}/.github/workflows/build.yml") && next_body=$(curl -sf "${base}/${sha:-main}/.github/workflows/build_next.yml"); then
            registry=$(printf '%s' "$body" | grep -m1 -o "inputs.duckdb_version || 'v[0-9][0-9.]*'" | grep -o "'v[0-9][0-9.]*'" | tr -d "'" || true)
            registry_next=$(printf '%s' "$next_body" | grep -m1 -o "duckdb_version: *'v[0-9][0-9.]*-[a-z]*'" | grep -o "'v[^']*'" | tr -d "'" || true)
            if [ -z "$registry" ] || [ -z "$registry_next" ]; then
              echo "::error::community-extensions at ${sha:-main} was fetched but build.yml/build_next.yml carry no recognisable duckdb_version (default='${registry}', next='${registry_next}'); this check's parse is wrong about the registry, fix the check"
              echo "duckdb-pin: FAILED, registry files fetched but unparseable" >> "$summary"; exit 1
            fi
            if [ "$registry" != "$DUCKDB_VERSION" ] || [ "$registry_next" != "$DUCKDB_NEXT" ]; then
              echo "::error::the community registry builds default=${registry} next=${registry_next} (at ${sha:-main}) but this repo ships default=${DUCKDB_VERSION} next=${DUCKDB_NEXT}; update the pin, the constants and the build jobs to the registry's lines"
              echo "duckdb-pin: FAILED, registry ${registry}/${registry_next} vs repo ${DUCKDB_VERSION}/${DUCKDB_NEXT}" >> "$summary"; exit 1
            fi
            mode="checked against the registry (default ${registry}, next ${registry_next}, at ${sha:-main})"
          else
            echo "::notice::could not reach the community registry; the pin was checked against the local constants only"
            mode="NOT checked against the registry (unreachable); local constants ${DUCKDB_VERSION}/${DUCKDB_NEXT} only"
          fi
          echo "duckdb-pin: OK, pin ${have:0:10} == ${DUCKDB_VERSION}; ${n} stable and ${m} next build job(s); ${mode}" | tee -a "$summary"
```

- [ ] **Step 1: Replace the `SetChildCardinality` `#ifdef` with a member probe**

Replace the block from `#ifdef DUCKDB_HAS_NEW_VECTOR_HEADERS` (the one wrapping `CompatSetOutputCardinality`) through its `#endif` with:

```cpp
// --- Output chunk finalization (change class 18) ------------------------------
// v2.0 gives every Vector its own size; DataChunk::SetCardinality updates only the
// chunk count, and SetChildCardinality sizes the children too. Probed on the MEMBER
// that changed, not on list_vector.hpp's presence: they shipped together once,
// which is not a reason to make one imply the other. Templates, because tag
// dispatch only defers the unselected branch when it is a template.
template <class T, class = void>
struct CompatHasSetChildCardinality : std::false_type {};
template <class T>
struct CompatHasSetChildCardinality<T, decltype(void(std::declval<T &>().SetChildCardinality(idx_t(0))))>
    : std::true_type {};

template <class CHUNK>
inline void CompatSetOutputCardinalityImpl(CHUNK &chunk, idx_t count, std::true_type) {
	chunk.SetChildCardinality(count);
}
template <class CHUNK>
inline void CompatSetOutputCardinalityImpl(CHUNK &chunk, idx_t count, std::false_type) {
	chunk.SetCardinality(count);
}
inline void CompatSetOutputCardinality(DataChunk &chunk, idx_t count) {
	CompatSetOutputCardinalityImpl(chunk, count, CompatHasSetChildCardinality<DataChunk>());
}
```

- [ ] **Step 2: Select the `Vector::Reference` arity by probing the one-argument form**

Replace the `#ifdef DUCKDB_HAS_COUNT_T` / `#else` / `#endif` block around `CompatReferenceValue` with:

```cpp
// --- Vector::Reference(Value) (change class 10) --------------------------------
// v1.5: Reference(const Value &)            v2.0: Reference(const Value &, count_t)
// The one-argument form is GONE on v2.0. Probe for THAT form, the thing that
// changed. count_t itself cannot be named on v1.5 (it does not exist, and a
// non-dependent absent name is a hard error even in an untaken template branch),
// so the two-argument branch stays behind the size.hpp include guard, which is
// the one question __has_include answers reliably: does this type exist.
template <class T, class = void>
struct CompatHasReferenceValueOnly : std::false_type {};
template <class T>
struct CompatHasReferenceValueOnly<T, decltype(void(std::declval<T &>().Reference(std::declval<const Value &>())))>
    : std::true_type {};

template <class VEC>
inline void CompatReferenceValueImpl(VEC &vec, const Value &value, idx_t count, std::true_type) {
	(void)count;
	vec.Reference(value);
}
#ifdef DUCKDB_HAS_COUNT_T
template <class VEC>
inline void CompatReferenceValueImpl(VEC &vec, const Value &value, idx_t count, std::false_type) {
	vec.Reference(value, count_t(count));
}
#endif
inline void CompatReferenceValue(Vector &vec, const Value &value, idx_t count) {
	CompatReferenceValueImpl(vec, value, count, CompatHasReferenceValueOnly<Vector>());
}
```

// v2.0 deletes ConstantExpression(const Value &) ("Values are not literals -- use
// ConstantExpression::FromValue"); v1.5 has the constructor and no FromValue.
// Probe FromValue, the thing that changed. From duckdb_markdown c86abc0.
template <class T, class = void>
struct CompatHasFromValue : std::false_type {};
template <class T>
struct CompatHasFromValue<T, decltype(void(T::FromValue(std::declval<const Value &>())))> : std::true_type {};

template <class CE>
inline unique_ptr<ParsedExpression> CompatConstantImpl(Value value, std::true_type) {
	return CE::FromValue(value);
}
template <class CE>
inline unique_ptr<ParsedExpression> CompatConstantImpl(Value value, std::false_type) {
	return make_uniq<CE>(std::move(value));
}
//! A parsed expression for a literal value, on either DuckDB line.
template <class CE = ConstantExpression>
inline unique_ptr<ParsedExpression> CompatConstant(Value value) {
	return CompatConstantImpl<CE>(std::move(value), CompatHasFromValue<CE>());
}

namespace compat_detail {
struct HasFromValueProbe {
	explicit HasFromValueProbe(const Value &) = delete;
	static unique_ptr<ParsedExpression> FromValue(const Value &);
};
struct NoFromValueProbe {
	explicit NoFromValueProbe(Value);
};
static_assert(CompatHasFromValue<HasFromValueProbe>::value, "CompatHasFromValue must detect FromValue (v2.0 shape)");
static_assert(!CompatHasFromValue<NoFromValueProbe>::value, "CompatHasFromValue must not fire without FromValue (v1.5 shape)");
} // namespace compat_detail
